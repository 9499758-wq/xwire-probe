> 如何把开源模型适配到你自己的 coding agent 上。@ClementDelangue 和 @huggingface 团队给出的一份非常具体的操作指南：他们用 RL 加一个小 LoRA，把 @Alibaba_Qwen 的 Qwen3.8-27B 在 SWE-bench Pro（hard 51）上从 39% 提到 65%：
> 1. 保留 harness，改造模型。同一个模型在不同 harness 里表现不一样，每个 harness 都有自己的工具、prompt 和控制流。所以与其换 harness 去追求更好的模型，不如针对每个 harness 训一个小 LoRA adapter，直接换到你已经在用的 agent 后面。第一个是给 @pidotdev 做的。
> 2. 在真实、未经改动的 harness 里训练。harness 原样运行，每次 rollout 都在自己的 sandbox 里，训练用的就是 harness 实际看到的那些 token。没有重新 tokenize，也没有把 agent 简化一份。
> 3. 先奖励正确性，再奖励效率。奖励由任务 verifier 的正确性，加上权重 0.1 的工具效率 bonus 组成。任务：750 个 scale800 任务混合 300 个 TermGrade 任务，每个任务 8 次 rollout。
> 4. adapter 保持小。LoRA r = 32，alpha = 64，作用在 attention 和 MLP 投影上。TRL 里的异步 GRPO，学习率 2e-5，每个 harness 2× B200。发布的 checkpoint 是 step 160。训练在计划的 1,000 步中的第 191 步被停掉。
> 5. 训练中拦截 reward hacking。一个叫 safeagents 的 proxy 会检查每一次工具调用。明显的 hack reward 尝试会被拦下并记 0 分。在早先的一次消融里，打开这个防护对准确率的影响是 +0.0 ± 4.1 个点。它不带来任何成本。
> 6. 保持 thinking 关闭。关掉 thinking 时，adapter 就能追平 base model 在最高 reasoning effort 下的表现：SWE-bench Pro 上 64.7% 对 64.7%，Terminal-Bench 2.1 上 56.6% 对 54.2%，token 用量少约 4.5 倍。给 adapter 打开 thinking 没有任何增益。
